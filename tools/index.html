NXS Site

This website. Content in TOML. Graph-driven build. Stateless output.

Available

The nex-ovia.com website is itself an NXS tool — a demonstration that the standard applies to any kind of project. Content is declared in TOML files. A build graph transforms them into HTML. The theme is a TOML declaration. Adding a connector makes it dynamic. The source is open.

  • Content declared in TOML — editable by anyone
  • Theme declared in TOML — change once, update everywhere
  • Graph-driven build pipeline with declared nodes and edges
  • Stateless HTML output — deployable anywhere for free
  • Dynamic-ready via connector pattern

NXS CLI

Scaffold, validate, visualise, and document any project from a single declaration.

In Development

A Rust binary that reads your project declaration and does the work of a senior engineer setting up a new repository. Generates the folder structure, wires the connections, validates compliance against NXS rules, and produces documentation automatically. Works with any language.

  • Scaffold any project from a TOML declaration
  • Validate NXS compliance before every commit
  • Generate dependency graphs from project structure
  • Produce documentation that stays in sync
  • Single binary — no runtime required

NXS Visualiser

See your project as a graph. Understand it without reading the code.

Planned

A visual dependency and workflow graph generated directly from your project structure. Not a diagram you maintain — a live rendering of what your project actually is. Every component, every connection, every decision point. Readable by anyone on the team.

  • Live graph from project structure — no manual diagramming
  • Dependency surface area visible at a glance
  • Decision flow and conditional paths rendered clearly
  • Embeddable in any documentation site
  • Exports to SVG, PNG, and Mermaid

NXS Docs

Documentation generated from the way your project is built, not what you remember to write.

Planned

Automatically generated documentation from a compliant NXS project. Pulls component descriptions, dependency declarations, input and output definitions, and the Definition of Done checklist into a readable, navigable site. Never out of sync because it is generated from the source of truth.

  • Auto-generated from project declaration — no manual writing
  • Always in sync — generated at build time
  • Readable by non-developers and engineers equally
  • Versioned alongside the project
  • Stateless HTML output — deployable anywhere
